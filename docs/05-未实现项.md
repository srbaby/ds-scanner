## 一、已知未实现（功能确实缺，但不擅自补）

### 1.1 熔断没有触发逻辑

`automation/observe.py` 输出的 `circuit_breaker.status` **硬编码为 `"normal"`**、
`message` 硬编码为 `"未触发熔断"`，三个 `condition_*_progress_pct` 只是进度显示。
**即使最大回撤达到 25%，面板仍显示"正常"。** 另外 `condition_b_progress_pct` 恒为 0，
条件 B 根本没实现。

阈值定义见 `X-Plan.md` 模块10。是否补触发逻辑待决策。

### 1.2 政策事件台账未持久化

`data/policy_research/events/*.jsonl` 在 GitHub Actions 里是**一次性目录**——
既不提交回仓库，也不从 Gist 恢复。因此 `extract_policy_events.py` 的
`existing_ids()` 去重每次都从空集开始。

后果：**真实发布日期解析失败的源站，其事件永远不会随时间过期**
（只是被 `published_at_estimated` 限权到 0.5，不再假装是当天发布）。
要根治需把事件台账落到 Gist，与 `holdings.json` 同级。

### 1.3 池外标的无风控

观察池外的持仓不参与扫描评分，因此没有 policy 总分、也不会触发 `RISK_STOP`。
目前靠人工纪律保证不持有池外标的。

### 1.4 `etf_base_config.json` 读取失败时的降级不够响

读失败会打印警告并退回硬编码兜底值。非交互环境（Actions）下自动继续。
兜底值与实际维护值偏差较大时，持仓止损判断可能失真。

## 三、方法论层面的待决事项

以下是业务判断题，不是工程缺陷，**需要大亨拍板**：

### 3.1 出场几何不对称

开仓要求现价 > MA20（常常刚刚站上，如 +0.46%），而 `TREND_BREAK` 在跌破 MA20 即触发——
**盈利侧出场线在入场时距离约 1%，亏损侧 `RISK_STOP` 在 −8%。**

实测：`TREND_BREAK` 平均 +2.07%，`RISK_STOP` 平均 −7.05%，
该参数组合隐含要求约 **77% 胜率**才能打平。

可选纠偏方向（均未实施）：要求取得最小有利位移后 MA20 移动止损才武装；
或按 ATR 而非 MA20 设置初始容忍带。

### 3.2 边际优势尚未在统计上确立

盈亏比 0.6467 < 1 → 盈亏平衡胜率 60.7%。当前胜率 78.95%，但 n=19，
Wilson 95% 置信区间 [56.7%, 91.5%]，**下沿低于平衡线**。
这是样本量问题，不是方法论已被证伪。

### 3.3 X-Plan 模块6「资金利用反馈」已触发

方法论自带条款：胜率持续 >70% 而总仓位长期 <30% 时应复查
"强信号开仓是否过小 / 确认加仓是否过严 / 盈利钝化是否过早 / 换仓是否过保守"。
当前胜率 78.95%、平均仓位 15.54%，**条件成立**，尚未复查。
