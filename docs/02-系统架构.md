## 一、全链路

```
Master-Scheduler（独立私有仓库，账户级基础设施）
    │ Service Binding 内网唤醒：周一至五 北京 12:00 / 14:49 发 scan，20:30 发 observe
    ▼
Cloudflare Worker  ds-scan-trigger
    │ repository_dispatch 触发（备用：浏览器访问 Worker URL 带 ?key= 手动触发）
    ▼
GitHub Actions（.github/workflows/scan.yml）
    │
    ├─ 1. npm run test:frontend + Python 回归测试
    │      ⚠️ 第一道门禁，红了后面全不跑，当天没 report / 没 Bark / 不写 Gist
    │
    ├─ 2. automation/policy_research/run_policy_research.py
    │      抓 31 个政务/行业源 → AI 归类判 ± → 按发布日期衰减 → 主题 delta(±2)
    │      → data/policy_research/snapshots/last_delta.json
    │      归类走 ai_classify.py 两趟调 DeepSeek（第一趟选读、第二趟判方向），
    │        AI 挂了退回关键词兜底并在 report 与 Bark 显式标注（见 X-Plan 模块11）
    │      ⚠️ 必须在扫描器之前，否则政策影响不了当天建议（见 03 篇）
    │
    ├─ 3. automation/ds_scanner.py
    │      ├─ 读 last_delta.json → 政策 delta 叠加到 base 分（进四维政策催化位）
    │      ├─ 读 Gist etf_pool.json（上次 policy 分）/ holdings.json（当前持仓）
    │      ├─ 拉新浪实时行情 + AKShare 历史K线
    │      ├─ 重算 policy 分 → 写回 Gist etf_pool.json
    │      └─ 生成 report.txt + decision.json（扫描器权威决策）
    │
    ├─ 4. automation/generate_dashboard.py
    │      写回 Gist dashboard.json
    │      ⚠️ 每日流程不调用 AI：scan.yml 显式传 AI_PROVIDER=none
    │
    ├─ 5. automation/send_report.py
    │      Bark 推送 report.txt 全文（POST JSON，badge 红点 + icon）
    │
    └─ 6. 扫描健康门禁（在 Bark 之后，仅让 Actions 历史诚实）
    ▼
index.html（GH Pages，stock.bailuzun.com）
    ├─ 读 Gist holdings.json + dashboard.json
    └─ 登记买卖/改资金 → 写回 holdings.json + execution_events_<年>.jsonl + data_manifest.json
    ▼
人工决策 → 14:55-15:00 执行
```

另有一条独立支线：`automation/observe.py`（每晚 20:30 由中控唤醒），维护交易台账与
方法论有效性统计，**不参与任何交易决策**。两个子系统的分工见 `01-业务意图.md` 第二节。

## 二、每日时间线

```
12:00  中控唤醒一次（盘中预览，报告头会标「下午盘中数据」且量比是外推估算值）
14:49  中控唤醒（正式）→ Actions 全流程
~14:51 dashboard.json 写回 Gist
~14:53 收到 Bark 推送，打开 stock.bailuzun.com 看扫描器操作清单
~14:55 人工决策确认（需二次分析时长按 Bark 复制 report 全文手动喂给 AI）
14:55-15:00  尾盘执行
收盘后 在网页更新持仓
20:30  中控唤醒 observe.py，更新台账与统计
```

⚠️ **盘中那次不是定稿**：报告头部会写「请在14:55重新运行」，量比按时间系数外推，
是当日最不可靠也最可能变脸的字段。决策一律以 14:49 那次为准。

## 三、Gist 数据契约

单个私有 Gist（Description: `ds_scanner`）。可用 `gh api gists/<id>` 直接读，
`gh api --method PATCH gists/<id> --input body.json` 直接写
（`gh` 已用仓库 owner 账号登录，带 `gist` scope）。

### 使用中的文件

| 文件 | 说明 | 谁写 |
| --- | --- | --- |
| `etf_pool.json` | ETF 池 policy 总分（base+tech+strength），每日跑完自动写回 | 脚本 |
| `holdings.json` | 当前持仓（现金、代码、数量、成本、买入日期） | 网页 |
| `dashboard.json` | 看板数据：report 原文 + `ai`/`audit`（当前 `enabled:false`） + `decision.operations`（扫描器权威操作清单，**结构化字段**，前端靠它做三态匹配，不是解析 report 里的 markdown 表格） + `policy_research` 旁路 + 生成时间/方法论版本 | `generate_dashboard.py` |
| `execution_events_<年>.jsonl` | 买卖/改资金/更正的完整台账，append-only。`event_type`：`BUY`/`ADD`/`REDUCE`/`SELL`/`CASH_UPDATE`/`CORRECT_REASON`/`REVERSE_EVENT` | 网页（`js/app.js` 的 `buildExecutionEvent`/`persistExecution`） |
| `data_manifest.json` | 上述 jsonl 的元信息（row_count / content_bytes / content_sha256 / last_event_id），每次写 execution_events 时同步重算 | 网页 |
| `stats.json` / `observer_state.json` | 方法论有效性统计 / 观察器状态 | `observe.py` |
| `trades_<年>.jsonl` / `portfolio_snapshots_<年>.jsonl` | 交易明细与净值快照 | `observe.py` |

### 台账 append-only，从不原地改历史

纠错追加 `CORRECT_REASON`（带 `target_event_id`/`previous_rule_code`），
撤销追加 `REVERSE_EVENT`，展示层把最新更正盖在原记录上。
**业务理由见 `01-业务意图.md` 第五节——能被改写的台账等于没有台账。**

### 遗留/归档（只读，不再写入）

`trades.jsonl`、`portfolio_snapshots.jsonl`——已迁移到年度分片，
`data_manifest.json.legacy_files` 里标了 `migrated_to`。
`report.txt` 是当次 `report` 字段的纯文本副本，给 Bark 推送用。

### 读取优先级

Python 侧：**Gist > 本地文件 > 硬编码兜底**。本地跑时不设环境变量自动降级本地文件。

⚠️ **本地仓库的 `data/*.json` 是历史快照**，不可据此判断当前持仓或分数。
唯一需要本地手工维护的是 `data/etf_base_config.json`（改完 push 生效）。

## 五、环境变量（GitHub Actions Secrets）

| 变量名 | 说明 |
| --- | --- |
| `DS_SCANNER_GIST_ID` | Gist ID（32位） |
| `GITHUB_TOKEN` | 有 gist scope 的 PAT，Secret 名为 `GH_PAT` |
| `BARK_KEY` | Bark 推送 key（不带 `https://api.day.app/` 前缀，与 fund-monitor 同一套） |
| `DEEPSEEK_API_KEY` | **政策事件归类用（v3.3 起生效）**，注入给 `run_policy_research.py`。缺失或调用失败 → 整体退回关键词兜底，并在 report 与 Bark 显式标注 |
| `DEEPSEEK_MODEL`（可选） | 默认 `deepseek-v4-flash` |
| `POLICY_AI_READ_BUDGET`（可选） | 默认 45，第二趟最多读几条正文 |
| `POLICY_AI_MIN_PER_SECTOR`（可选） | 默认 2，每个 ETF 板块保底送读几条 |

下面这组只跟**每日 AI 审计**有关，与上面的政策归类是两回事：

| 变量名 | 说明 |
| --- | --- |
| `AI_PROVIDER`（可选） | `none`（默认，`scan.yml` 显式传入）/ `gemini` / `deepseek`。**审计流程恒为 none**，下面几个变量当前都不生效 |
| `GEMINI_API_KEY` | 仅 `AI_PROVIDER=gemini` 时使用 |
| `GEMINI_MODEL`（可选） | 默认 `gemini-3.5-flash` |
| `GEMINI_THINKING_LEVEL`（可选） | 默认 `high`；仅 3.x 系列支持，切回 2.x 需清空 |

## 六、前端分层

单页 `index.html` 是壳，逻辑都在 `js/`，**按顺序加载、共享全局作用域**
（为什么不用 ES module 见 `03-实现约束.md`）：

```
js/api.js       Gist 读写封装（GistClient / GistApiError / parseJson / parseJsonl），不碰 DOM
js/decision.js  纯函数：动作优先级排序、dashboard 新鲜度判断
js/app.js       主逻辑：渲染、持仓登记、扫描器建议三态匹配、执行事件构建与写回（~2400行）
css/style.css   全部样式，含桌面表格的 grid-template-columns（按实测字符宽度定宽）
```

页面自上而下三块：

| 区块 | 功能 |
| --- | --- |
| 持仓管理（置顶） | 可用资金/持仓列表，买入建仓（代码自动联想补全池内 ETF）/ 减仓（标记 `is_reduced`）/ 清仓 / 改数量、成本、买入日期。实时写回 Gist |
| 🤖 今日AI审计（当前停用） | `AI_PROVIDER=none` 时显示「每日AI审计已停用／操作清单由扫描器确定性生成」并折叠 |
| 📡 原始扫描数据（默认折叠） | report.txt 原文；无 decision 或 AI 异常时自动展开作人工兜底 |

GitHub Token + Gist ID 存浏览器 localStorage，登录一次后自动读取。
